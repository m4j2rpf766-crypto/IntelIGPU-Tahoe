# FollowUpUI 地图黑框兼容

2026-09-21 已在验证机器部署，用户确认真实 Apple 账户弹窗地图恢复；新系统 FollowUpUI 的库映射和合成/同步调用均已核实。本目录只包含原创源码和脱敏说明，不包含 Apple 二进制、地图图片或账户日志。

## 复现与原因边界

不依赖 MapKit 的最小复现：356×183 BGRA8_sRGB、4 样本纹理清屏后执行原生 resolve，再同步并读回。第一次结果全零、第二次正确，命令均报告 completed；同阶段与分阶段 resolve 均复现，单样本清屏正常。独立 compute 读取 resolve 前的四个样本，确认首次源颜色正确。因此问题集中于首次原生 MSAA 合成；原生驱动内部初始化或状态错误的具体原因尚未完全查明。

之前只替换 managed 纹理同步的方案仍间歇全黑，不能修复合成阶段已产生的零图像。

## 实现

- Factory 只在 `FollowUpUI` 中加载 `libReimsMapResolve.dylib`，不对 WindowServer 或其他应用启用。
- 兼容单颜色附件、4 样本、BGRA8/BGRA8_sRGB、二维、零 slice/level、源目标同尺寸的 resolve。其他路径保持原实现。
- 保留 MSAA 源的 store，在原 command buffer 中追加全屏三角形绘制，对全部样本在线性颜色空间平均，并写入同格式目标。保留 4 倍抗锯齿、真实命令完成和上传顺序，不添加帧率限制。
- 对进程内相关格式的二维纹理创建明确声明 shader-read/render-target 用途；已有用途不兼容的纹理不进入替代路径。描述符先复制，不改调用方对象。
- 保留 managed 二维单层纹理的逐 mip 同步兼容；严格核对原生方法所属镜像和已审查偏移。Factory 的既有 UUID 预检继续约束原生驱动版本。

## 构建与验证

`bash scripts/build-userspace.sh` 构建 factory 和正式地图库。部署须同时放置两者并对完整 Metal 包签名，见[部署说明](../docs/DEPLOY-SAME-HARDWARE.md)。已有安装先完整备份，在副本中准备并验证后统一替换；回退恢复整个旧包。旧 FollowUpUI 进程须退出后重新触发账户提示，不需要重启 WindowServer，也不要自动操作账户允许/拒绝按钮。

已激活兼容核显的验证机器可显式运行：

```sh
bash scripts/test-map-resolve.sh
```

这会提交真实 GPU 工作，但不安装驱动、不接管桌面。构建目录保存输出。`checks/msaa_samples.swift` 为独立源样本诊断，`inspect` 参数会在 resolve 前读出四个样本；它不加载补丁，可用于观察原生行为。最小复现程序的退出码为非零时表示某次提交失败或读回首像素为零，不代表完整像素比较已经通过。

本次验收包括同阶段/分阶段的首次和第二次合成、单样本对照、三个全新 MapKit 进程、安装后无注入环境变量的自动加载探针，以及用户确认的真实弹窗。地图与正常原生输出相比，8 个颜色通道变化、最大差异 2/255；不声称逐字一致或覆盖所有样本分布、格式与应用。其他 GPU 挂起和长期稳定性仍是独立问题。
